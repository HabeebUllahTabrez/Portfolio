How I work

From the problem to the product

  1. Start with the problem

    Understand who it’s for and what they actually need. Ask why before how, and agree on the shape of the solution before any code.

  2. Design the system

    Data first: clean schemas, clear APIs, and a plan for how it holds up when usage grows.

  3. Build it end to end

    Backend is home, but I build the frontend and design the interface too, using AI to move fast without cutting corners.

  4. Make it fast, keep it running

    Indexing, query plans, and refactoring for scale, so it keeps working after launch day.
